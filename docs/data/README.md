# Demo data

All files here are generated by `python3 docs/data/build_data.py` from the research data in this repo.
Only self-generated puzzles are used.

- `pool.json`: the 300 graded puzzles of `levelgen/pool/pool.json` (N=6-9; level T3, T3b, T4, T5a, T5b = reasoning-technique tier needed; each has a unique solution).
- `s5.json`: the first puzzle of each size N=11..16 from `bench/suites/S5.json` (random unique-solution boards), for the "Large" setting of Play.
- `race.json`: the curated Race puzzles, with the C++ reference numbers from the benchmark CSVs where they exist.

## How the Race puzzles were picked

Node counts come from `bench/results/extra_S3n25_t60.csv` (S3 N=25, 60 s timeout) and `bench/results/unified_S6m.csv` (S6m). Both solvers run the same branching order, so the node ratio isolates the effect of the Hall check.

1. Group "hall" (S3, N=25, random regions). Aim: show the case where plain bitmask DFS is hopeless and matching is instant. Picked by C++ result:
   - `S3-n25-17`: bitmask timed out at 60 s (124 M nodes), unsatisfiable, match needs 1 node.
   - `S3-n25-11`: unsatisfiable, bitmask 84.9 M nodes (54 s), match 1 node.
   - `S3-n25-01`: unsatisfiable, bitmask 19.1 M nodes (10.8 s), match 1 node.
   - `S3-n25-09`: satisfiable, bitmask 647,686 nodes vs match 3,063 (a case with a real search on both sides, ratio 211x, finishes in the browser).
   - `S3-n25-06`: unsatisfiable, 113,639 vs 1 node (small enough to finish in the browser quickly).
   The default 20 M-node cap lets the 19 M one finish in the browser and cuts off the 60 s-timeout ones, which then read "exceeded N nodes".
2. Group "hard" (S6m, adversarially hill-climbed against match, unique solution). Aim: both solvers have to search. Picked the puzzles with the largest bitmask node counts per size, plus one N=14 case: `S6m-mt-n18-4` (3.57 M vs 0.40 M nodes), `S6m-mt-n18-1` (2.06 M vs 0.31 M), `S6m-mt-n16-0` (0.75 M vs 0.17 M), `S6m-mt-n14-1` (0.34 M vs 0.18 M). Here the node ratio is 2-9x, not thousands.
3. Group "anim" (N <= 10, for the step-by-step replay). Short searches so the whole run can be watched: `S3-n10-05` and `S3-n8-05` (unsatisfiable; bitmask 32 / 25 nodes, match prunes at the root), `L9-normal-007` and `L9-normal-013` from the playable pool (unique solution; 70 vs 19 and 86 vs 37 nodes, the biggest ratios among pool puzzles with at least 60 bitmask nodes). Node counts of these four were computed with the JS solver, which equals C++ node-for-node (see `tests/test_demo_js.py`).

Honest caveat: on the playable pool (N=6-9) the two solvers differ by only about 1-4x in nodes; the large gaps only appear on large or unsatisfiable boards.
